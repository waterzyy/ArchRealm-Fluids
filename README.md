# ArchRealm Fluids

[![build](https://github.com/waterzyy/ArchRealm-Fluids/actions/workflows/build.yml/badge.svg?branch=main)](https://github.com/waterzyy/ArchRealm-Fluids/actions/workflows/build.yml)
[![license](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Реалистичная вода и лава для **Minecraft 26.3 / Fabric**: конечные объёмы вместо бесконечных
источников, гидростатическое давление, затопления, сливы, пар и свет от лавы.

## Возможности

**Вода и лава как объём.** Каждая ячейка хранит от 0 до 8 единиц жидкости: полный блок — 8 единиц,
ведро — одно ведро. Жидкость конечна и не размножается, а её объём сохраняется — солвер не создаёт и
не уничтожает единицы ни при перетекании, ни при падении с обрыва.

**Гидростатика.** Давление считается обходом связной области жидкости, поэтому работают
сообщающиеся сосуды: вода поднимается во втором колене U-образной трубы и в колодце до уровня
водоёма. Плоская лужа при этом спокойна — давление учитывает только реальный напор.

**Затопления и сливы.** «Реальный источник воды» и «Реальный источник лавы» работают как краны: пока
включены, подают по единице каждые 10 тиков. «Реальный слив» забирает жидкость, и вода стекается к
нему со всей связной области.

**Реакции.** Лава светится, причём яркость зависит от количества лавы в ячейке, поджигает горючее и
шипит, встречаясь с водой, превращаясь в камень или обсидиан и давая пар. Вода тушит огонь,
увлажняет грядки и снимает горение с попавших в неё сущностей.

**Слизневые и медовые блоки.** Желеобразные блоки пружинят и замедляют, а при шаге и приземлении
деформируются — сплющиваются и растягиваются.

**Сохранение.** Жидкость хранится в обычных блочных состояниях, поэтому переживает выгрузку чанка и
перезапуск сервера. Участки далеко от игроков «паркуются»: они продолжают течь по упрощённому
правилу, а когда игрок возвращается, снова попадают в полную симуляцию.

## Установка

| Компонент | Версия |
|---|---|
| Minecraft | 26.3 |
| Fabric Loader | 0.20.1 или новее |
| Fabric API | 0.165.0+26.3 |
| Java | 25 |

1. Установите [Fabric Loader](https://fabricmc.net/use/installer/) для Minecraft 26.3.
2. Скачайте последний `archrealm_fluids-*.jar` со страницы [Releases](../../releases).
3. Положите его в папку `mods` вместе с [Fabric API](https://modrinth.com/mod/fabric-api).

Мод работает и на клиенте, и на сервере. На сервере он самодостаточен: физика считается на стороне
сервера, клиент нужен только для вида воды, настроек и рендера блоков.

## Сборка из исходников

```bash
./gradlew build     # готовый jar появится в build/libs
./gradlew test      # модульные тесты солвера
```

Проект собирается на JDK 25 (Gradle toolchain подхватит его автоматически).

## Управление

| Клавиша по умолчанию | Действие |
|---|---|
| `M` | экран настроек мода |
| `N` | вид воды: `поверхность` ↔ `частицы` |
| `B` | оверлей производительности |

Все клавиши переназначаются в обычных настройках управления, категория **ArchRealm Fluids**.

## Команды

Серверные, требуют прав оператора:

| Команда | Действие |
|---|---|
| `/arfluids stats` | активные и отложенные ячейки, очередь чанков, работа за шаг |
| `/arfluids clear [радиус]` | убрать реальную жидкость вокруг себя |
| `/arfluids wake [радиус]` | заставить симуляцию заново просмотреть чанки |
| `/arfluids reload` | перечитать конфигурацию |
| `/arfluids version` | версия мода |

Клиентские:

| Команда | Действие |
|---|---|
| `/fluid stats` | сколько жидкости видно рядом, текущий вид, FPS |
| `/fluid clear` | попросить сервер убрать жидкость вокруг |
| `/fluid view mesh\|fluid` | переключить вид воды |

## Конфигурация

Файл `config/archrealm_fluids.json` создаётся при первом запуске. Значения проверяются при загрузке:
некорректные исправляются и записываются обратно, а повреждённый файл сохраняется отдельно как
`archrealm_fluids.json.broken` — из-за конфигурации мод не падает.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | главный выключатель симуляции |
| `cellUpdatesPerStep` | `2048` | сколько ячеек может обработать один шаг |
| `stepsPerSecond` | `10` | частота шагов симуляции |
| `pressure` | `true` | гидростатическое давление |
| `pressureMaxCells` | `1024` | максимальный размер связной области для давления |
| `pressureWorkBudget` | `8192` | бюджет обхода для давления за шаг |
| `viscosity` | `1` | вязкость: лава движется в 4 раза медленнее воды |
| `simulationRadius` | `128` | предел дистанции симуляции, `0` — без предела |
| `waterDistance` | `96` | дальше этого вода паркуется |
| `lavaDistance` | `48` | дальше этого лава паркуется |
| `parkedFlow` | `true` | упрощённое течение отложенной жидкости |
| `parkedIntervalTicks` | `4` | как часто обновляется отложенная жидкость |
| `parkedCellsPerTick` | `64` | бюджет отложенных ячеек |
| `wakeOnChunkLoad` | `true` | будить жидкость при загрузке чанка |
| `wakeChunksPerTick` | `2` | сколько чанков просматривать за тик |
| `waterLavaReaction` | `true` | вода и лава дают камень, обсидиан и пар |
| `lavaIgnitesFire` | `true` | лава поджигает горючее |
| `waterExtinguishesFire` | `true` | вода тушит огонь |
| `waterHydratesFarmland` | `true` | вода увлажняет грядки |
| `reactionParticles` | `true` | частицы пара и брызг |
| `debugOverlay` | `false` | оверлей производительности |
| `startInParticleView` | `false` | начинать с вида «частицы» |

## Как это работает

```
dev.archrealm.fluids
├── sim/        чистое ядро: сетка, солвер, очередь активных ячеек, настройки
├── config/     конфигурация и её безопасное чтение/запись
├── registry/   жидкости, блоки, предметы, block entity, creative tab
├── world/      блоки жидкости, кран, слив, реакции, движок симуляции
├── item/       вёдра
├── command/    /arfluids
└── client/     вид воды, экран настроек, оверлей, рендер желе, /fluid
```

Пакет `sim` ничего не знает о Minecraft: это набор целочисленных операций над сеткой, поэтому солвер
прогоняется обычными JUnit-тестами. Движок раз в шаг отдаёт ему ограниченное число активных ячеек,
а блоки жидкости хранят результат в своих состояниях.

Рендер — ванильный: мод регистрирует `FluidModel` и разрешает стандартному тесселлятору рисовать
поверхность, поэтому Sodium, Iris и шейдеры видят привычную геометрию.

## Производительность

* Работа ограничена бюджетом: за шаг обрабатывается не больше `cellUpdatesPerStep` ячеек, обход
  давления ограничен и по размеру области, и по числу посещений.
* Успокоившаяся жидкость убирается из очереди и не стоит ничего, пока рядом что-то не изменится.
* Дальняя жидкость считается по дешёвому правилу с отдельным маленьким бюджетом.
* Чанки просматриваются при загрузке, по команде и периодически вокруг игроков — а не каждый тик.
* Ванильные тики текучести отключены, запись идёт без каскадных обновлений соседей.
* Солвер пишет только в воздух, заменяемые блоки и такую же жидкость, поэтому постройки не страдают.

## Совместимость

Мод использует стандартный конвейер рендера жидкостей и не вмешивается в шейдеры, поэтому работает
с Sodium, Iris и ресурспаками, меняющими текстуры воды и лавы.

## Отличия от GPU-реализаций

Идейный вдохновитель — мод *Realistic Fluids - GPU Water & Lava*. Здесь применён другой подход:
физика считается на CPU на стороне сервера, а не частицами на видеокарте. Это даёт одинаковый мир у
всех игроков, не требует OpenGL 4.6 и compute-шейдеров и позволяет хранить объём в блоках, но
поверхность получается ванильной, без мягкой деформации частиц.

Код, ассеты и формат данных в этом репозитории написаны с нуля; исходный мод распространяется под
лицензией All Rights Reserved и не использовался.

## Ограничения

* Жидкость течёт только в загруженных чанках; в выгруженных она остаётся в блоках.
* Отложенная жидкость выравнивается грубее, чем в зоне симуляции.
* Ведро переносит ровно ведро (8 единиц); частично заполненную ячейку можно осушить сливом.
